# Dummy Data TODO

## Description

Dummy data should be generated with the Faker package to create realistic enough sewage pipe cleaning, inspection, and repair records. It should be implemented as a dedicated Docker Compose service with its source code in `faker/`.

Use the default/base Faker locale unless a more specific locale is chosen during implementation. The data does not need to be highly realistic, but it should feel plausible for a German sewage pipe cleaning context. Generated data should be written as JSON to a local `data` folder instead of inserted into PostgreSQL directly. Applicants can use those files to design and populate their own schema.

The `data/` folder should be created by the generator command. It should not be committed with a `.gitkeep`.

The generator should be simple and should not be part of the applicant task. It may include occasional missing optional values such as description or location, but should avoid deliberate edge-case traps. Generated files should be overwritten by default.

Generate separate `customers.json` and `projects.json` files. These generated files should be created by the applicant as a setup step and should not be committed to the applicant branch. Generate 10 customers and 100 projects. Project dates should be between `2022-07-01` and `2023-07-30`. Municipalities should be sampled from northern Germany using implementation judgment. Project tasks are `cleaning`, `inspection`, and `repair`. Project statuses are `open`, `in progress`, and `done`. The deterministic Faker seed may be chosen during implementation.

## Likely Data Categories

- Customer names with addresses
- Projects
- Locations or municipalities
- Project task text sampled from a short list
- Project date
- Project description, optionally missing
- Project status
